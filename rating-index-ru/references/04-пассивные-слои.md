# Фаза 4: пассивные слои (60 баллов вне замера) + контроль качества

Пассив — всё, что снимается без единой заявки: карты, сайты, соцсети, агрегаторы, ИИ-видимость. Это 60 баллов из 100 и добрая половина времени фаз 4-6 — а ещё место, где легче всего соврать самому себе цифрами, потому что скрипт отработал и выдал результат, который никто не сверил с реальностью. Один принцип держит весь файл и должен держать твою голову: **ноль — это проверенный факт, н.д. — дырка в проверке.** Перепутал их местами — обвинил компанию в том, чего не смотрел, и первый же владелец, открывший свою карточку, поймает тебя на слове.

Карта границы ноль/н.д. по слоям — почему именно так, см. разделы ниже:

| Слой | Ноль (проверено) | Н.д. (не проверено) |
|---|---|---|
| Сайт | 404/403/5xx подтверждено повторной попыткой; сайта нет в карточке вообще | не открылся один раз (таймаут, сеть) |
| Карты: канал | заявлен, но живой человек не смог доставить заявку в волне | канал не проверялся (компания вне волны) |
| Соцсети | Telegram = чат по номеру, ВК не заявлен | ВК заявлен, но лента не просмотрена глазами |
| Яндекс.Карты | искали руками по названию/адресу — не нашли | парсер не открылся или нашёл другую организацию |
| Агрегатор ниши | страница открылась, поиском компания не найдена | агрегатор ограничил доступ / капча / не открылся |

## Сайты — HTTP-прогон всех точек

Прогони каждую точку обычным HTTP-запросом: код ответа, HTTPS, `viewport` (мобильная вёрстка), онлайн-запись, страницу или отметки цен, реквизиты (ИНН, юрлицо — где опубликованы).

- **404 / 403 / 5xx, подтверждено повторной попыткой** → мёртвый сайт → ноль сразу по всем пяти полям блока, а не только по «открывается». У мёртвого сайта физически не может быть ни записи, ни цен, ни мобильной вёрстки — не растягивай одну находку на одно поле, когда она закрывает весь блок разом.
- **Сайта нет в карточке вообще** → тоже ноль, но другая формулировка для разговора: «сайта нет» и «сайт есть, но лежит» — разные дыры, не путай их местами в скоркарте.
- **Таймаут** → сначала повторная попытка (http и https по очереди), и только если не открылся снова — переводи в подтверждённый ноль. Одна неудачная попытка — это н.д., а не ноль: сайт мог упасть на минуту от нагрузки, вменять это компании нечестно.

Ориентир по объёму на эталоне (306 точек): 91 без сайта, 9 подтверждённо мертвы, 33 без HTTPS. Больше трети живых сайтов — уже проверенно дырявые, находок хватит на всех.

## Карты — 2ГИС и Яндекс

С флагманского филиала (максимум отзывов) сними: рейтинг вместе с числом отзывов — сырые звёзды почти не различают (у большинства 4,5–5,0), поэтому 4,9 при 12 отзывах и 4,9 при 900 нормируются по-разному; число фото; награды («Хорошее место» у Яндекса); заполненность карточки (сайт, часы, email); отдельно — указан ли мессенджер-канал и работает ли он.

«Заявленный канал мёртв» — самостоятельная находка, а не то же самое, что «канала нет вообще»: компания, повесившая нерабочую ссылку на Telegram, обманывает ожидание сильнее, чем компания, честно ничего не указавшая. Источник признания «мёртв» — **только сама волна**: канал мёртв, когда живой человек не смог доставить заявку ни по одному заявленному каналу. Вне волны наличие канала засчитывается по презумпции, без проверки живости, — не выдавай одно за другое перед владельцем.

Для Яндекс.Карт (капчи агрессивные, покрытие будет неполным — это ожидаемо, см. `01-разведка-и-база.md`): «карточки нет» — дыра только при **подтверждённом руками** отсутствии по названию и адресу. «Парсер не открылся» или «нашлась другая организация» — сбой инструмента, а не факт о компании; в ноль это не идёт.

## Соцсети — kind + дата последнего поста

Проверь Telegram по форме ссылки: `t.me/<username>` открывает публичную ленту (`t.me/s/<username>`) — оттуда дата последнего поста. `t.me/+7XXXXXXXXXX` — личный чат по номеру, ленты у него нет и не может быть по устройству мессенджера, а не по недоработке скрипта.

«Чат по номеру» — это **проверенный** факт (ссылка открыта, ленты физически нет), поэтому при отсутствии заявленного ВК балл «живые соцсети» уходит в ноль, а не в н.д.: проверка состоялась, она просто выяснила, что смотреть нечего. Если ВК при этом заявлен, но ещё не просмотрен — балл висит в н.д. до ручной проверки, ставить ноль рано.

ВКонтакте скриптом не достаётся вообще — и `vk.com`, и `m.vk.com` отдают неавторизованному запросу страницу входа, а не стену. Планируй это как ручной пункт пользователю с первого дня, а не как аварийный докор перед сдачей. Формат ответа — одна строка на компанию, без ничего лишнего:
```
example_clinic — 12 июля
dental_demo — 26 июля
brand_three — постов нет с 2023
```

## Глубокий слой отзывов

Метрики строит `аудит_2gis_отзывы.py` через API отзывов (доступ и ключ — только законные, см. `01-разведка-и-база.md`). Слой идёт в скоркарты и бенчмарки наблюдением, не баллом методики (веса зафиксированы до его появления): медиана дней от отзыва до официального ответа, доля отвеченных за 365 дней, поток за 90/180 дней (с «≥», если уткнулись в лимит выборки раньше, чем в окно дней, — это оценка снизу, не точная цифра), негатив без ответа с датами, тренд «перестали отвечать» (отвечали в старых отзывах, в последних просели). Ориентир на эталоне: медиана ответа ≤7 дней — уже похвала, ≥30 дней — уже дыра для разговора, между ними — нейтрально.

Обязателен фильтр `not is_hidden and is_rated`: публичная лента 2ГИС показывает посетителю только `is_rated=true`, API отдаёт больше. Без фильтра цифры разойдутся с тем, что владелец увидит, открыв собственную карточку, — реальный случай на одной из клиник выборки (см. спот-чек ниже). Правило одной фразой: **считаем так, как видит посетитель**, а не так, как отдаёт API.

## ИИ-тест видимости

10 вопросов клиента × 4 ассистента × 2 прогона = 80 ответов, около часа работы. Каждый вопрос — новый чистый чат: история диалога меняет ответ. Два прогона обязательны, не один: ассистенты недетерминированы, одна удачная или неудачная выдача ничего не доказывает. Метрика — доля прогонов с упоминанием, а не сырое число упоминаний.

Словарь брендов в консоли — двухуровневый, и это не техническая деталь, а защита от лжи себе: обычные слова, совпадающие с именами компаний («Улыбка», «Здоровье»), автоматически идут только в жёлтые **кандидаты** — зачёт требует твоего клика по каждому отдельно. Не подтверждай слово, просто встретившееся в обычной фразе ответа; подтверждай только реальное упоминание компании (обычно с большой буквы или рядом со словом «клиника» — консоль подсказывает такие случаи). Пропустишь дисциплину клика — получишь дутую видимость и сгоришь на первом же владельце, который переспросит ассистента при тебе. Учитывай падежные хвосты («Примердент», «Примердента», «Примердентом») — без них тест недосчитывает половину настоящих упоминаний. Ноль по этому блоку — норма, а не приговор: у большинства компаний ноль, и именно поэтому пункт работает в разговоре — это разговор про завтрашний канал, который пока не занял никто.

## Агрегаторы по нишам

Ниша определяет набор агрегаторов — таблица ниже стартовый список для разведки (фаза 1), не догма:

| Ниша | Агрегаторы | Что снимать |
|---|---|---|
| Медицина | ПроДокторов, НаПоправку | профиль есть/нет, число врачей, число отзывов |
| Недвижимость | ЦИАН, ДомКлик, Яндекс.Недвижимость, Авито | рейтинг агентства/риелторов, число объектов в продаже, число отзывов |
| Автосервисы | Zoon, Авито, Дром | рейтинг, число отзывов, отвечают ли на отзывы |
| Юристы | Правовед, юрист.ру | профиль есть/нет, рейтинг, число отзывов/дел |
| Салоны красоты | Zoon, Яндекс | рейтинг, число отзывов, фото |

Два правила поверх таблицы:
1. **Не включай в веса методики источник, который не можешь гарантированно собрать.** Агрегатор, закрывающийся капчей чаще, чем открывающийся, идёт наблюдением в скоркарту при удаче, но не строчкой в весах — рейтинг с половиной «н.д.» по нише не ранжирует ничего.
2. **Агрегатор ограничил доступ — не обходи ограничение.** Профильные агрегаторы нередко блокируют сборщик уже после нескольких десятков запросов за сессию. Смена IP, решение капч и маскировка скрипта под человека — не наш метод. По порядку: снизить темп или остановиться; поискать официальный API или партнёрский доступ; короткий список проверить вручную в обычном браузере; остальное честно оставить в н.д. (и тогда — правило 1).

## Бенчмарки города

Квартили (`q1`/`med`/`q3`/`n`, минимум 8 значений на метрику) по всей приватной выборке города — не только по волне и не только по маршруту. Считает `бенчмарки()` в `артефакты.py`, кладёт в `бенчмарки.json`; пересчитывай при каждом обновлении слоя отзывов.

Это главная неповторимая ценность продукта, а не побочный отчёт: у владельца отдельной компании нет и не будет выборки в две-три сотни конкурентов — только у тебя. Каждая скоркарта обязана ставить компанию рядом с медианой и четвертями города («поток отзывов — 4 за квартал при медиане города 11, вы в нижней четверти»); без этого сравнения индекс — список чисел без масштаба.

## Спот-чек: протокол контроля перед тем, как поверить цифрам

Перед тем как отдать пассив в расчёт, проверь 5-6 компаний **разных профилей**, специально разных: явный лидер, явный ноль, «раньше отвечали — перестали», маленькая (мало отзывов), большая (сотни отзывов). Один профиль вместо пяти ничего не докажет — баг чаще всего живёт в пограничном случае, а не в среднем.

Метод: цифра скрипта против того, что видно живому человеку в открытой карточке (2ГИС — вкладка «Отзывы», сортировка **«По новизне»** обязательна, счёт официальных ответов в первых 10-20 руками). Протокол — таблицей в пруфы (`рейтинг\пруфы\спот-чек_*.md`): компания, профиль, цифра скрипта, цифра браузера, вердикт.

**Расхождение — это стоп, а не округление в свою пользу.** Реальный случай конвейера: у одной из клиник API показал 0 ответов из 10, браузер — 1 из 10. Причина оказалась не багом скрипта, а правилом видимости: публичная лента показывает только `is_rated=true`, а API отдавал и непроверенные отзывы тоже. Фильтр добавили, слой пересобрали целиком. Правило на будущее: **истина — то, что видит посетитель**; если цифра с этим расходится, чинить нужно цифру, а не спорить с браузером.
