# Делегирование: кто какую работу делает

Правило стоимости: основная сессия — дорогая и умная, субагенты — дешёвые и узкие.
Всё, что сводится к «повтори N раз по инструкции», уходит вниз по стоимости.

## Карта делегирования

| Работа | Исполнитель | Почему |
|---|---|---|
| Поиск API, дизайн методики, склейка, расчёт, спот-чек, выдача | основная сессия | решения и ответственность |
| API-скрипты сбора (2ГИС и т.п.) | основная сессия пишет, запускает фоном | 6 минут скрипта против часов браузера |
| Браузерный сбор с сайтов без API (агрегаторы ниши) | **отдельная сессия Sonnet, low effort, Chrome-расширение** | дёшево, параллельно основной работе |
| Механические правки по готовой спеке (UI консоли, генераторы) | fast-worker субагент | скорость; приёмка — основной сессией |
| Разведка большого репо/выгрузок | Explore субагент | не жечь контекст основной сессии |

## Шаблон промпта для браузерного Chrome-агента (выстрадан на агрегаторе отзывов о врачах и 2ГИС)

Обязательные элементы — каждый закрывает реальный сбой:

1. **Жёсткий формат результата**: JSON-файл по фиксированному пути, одна запись на компанию,
   схема с примером. Явное поле `found: true/false` («нет профиля» — это данные, а не пропуск)
   и `status: ok/не открылась`.
2. **Контекст-диета** (агент забил 200k контекста за 33 клиники — не повторяй): записывать
   ТОЛЬКО счётчики и короткие поля («26 врачей, 501 отзыв»), НИКОГДА не копировать тексты
   отзывов/описаний в заметки; после каждой компании — сразу в файл, не держать в голове.
3. **Сортировка и глубина явно**: «переключи сортировку на "По новизне" и подтверди это
   скриншотом первой страницы» — дефолтные сортировки («по доверию», «по полезности»)
   перемешивают даты, и «ответы из последних 10» превращаются в мусор.
4. **Чекпойнт каждые 10 записей**: дописать файл, сообщить прогресс числом.
5. **Запреты**: капчи не решать (стоп и доложить), блокировки и лимиты не обходить, никуда не
   логиниться, ничего не отправлять и не кликать кнопки действий, только чтение — и только
   там, где условия площадки это допускают.
6. **Устойчивость**: страница не открылась → status='не открылась', идти дальше; не зависать
   на одной компании дольше 2 минут.
7. **Порядок обхода**: приоритетные первыми (волна и целевые компании), чтобы обрыв на
   середине не обесценил прогон.

Мини-скелет промпта:
```
Собери данные с <агрегатор> по списку компаний из <файл со списком: имя, город, ссылка/поиск>.
На каждую компанию запиши в <путь>/результат.json одну запись:
{"name": "...", "found": true/false, "врачей": N, "отзывов": N, "status": "ok"}
Только счётчики из шапки профиля — тексты не копируй. Дописывай файл после каждой компании,
каждые 10 — сообщи прогресс. Сортировки: <явно>. Капча или блокировка → остановись и доложи.
Не логиниться, ничего не отправлять. Не открылась страница за 2 минуты → status "не открылась", дальше.
Порядок: сначала компании с пометкой priority.
```

## Чек перед тем, как сажать браузерного агента

- [ ] Я искал публичный или официальный API 15 минут? (документация площадки, network-вкладка, `*api*`-домены)
- [ ] Условия площадки допускают такой сбор?
- [ ] Я проверил дефолтную сортировку списка, который агент будет читать?
- [ ] Схема результата задана с примером и полем found/status?
- [ ] В промпте есть контекст-диета и чекпойнты?

Урок в одну строку: **полдня браузерного агента по 2ГИС с битой сортировкой заменились
6-минутным скриптом, когда нашёлся API.** Сначала API, потом браузер.

## Приёмка работы субагента — всегда основной сессией

Субагент отчитался «готово» — это начало приёмки, не конец работы: проверь файл на схему,
пересчитай 2-3 записи против живого источника, прогони спот-чек как в
`04-пассивные-слои.md`. Все реальные баги конвейера (сортировка «по доверию», невидимые
публике отзывы) находились именно на приёмке, а не в отчётах исполнителей.
