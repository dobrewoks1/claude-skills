# Индекс цифровой доступности: конвейер «ниша + город → скоркарты»

Проверенный на практике конвейер (стоматологии Омска, июль 2026): 306 точек 2ГИС → 229 брендов →
волна из 148 заявок → индекс /100 → персональные скоркарты как повод для разговора с владельцем.
Этот скилл — чтобы каждый новый рейтинг начинался с фазы 0, а не с чистого листа.

**Эталонная реализация** (код и данные прошлого замера; в публичную версию скилла не входит):
`<путь к эталонной реализации>`
— `инструменты\` — все скрипты конвейера (копируй в новый проект и адаптируй, список ниже);
— `рейтинг\МЕТОДИКА.md` — эталон методики; `рейтинг\веса_v1.json` — эталон весов;
— `<путь к сборщику каталога 2ГИС>` — сборщик через официальный Catalog API 2ГИС (README внутри);
— `база\*.csv` — СТАРЫЕ выгрузки: **образец схемы колонок и метода, НЕ данные**.
Если эталона нет на диске — спроси пользователя, где он, прежде чем писать код с нуля. Если его
нет вовсе — таблица инструментов ниже служит спецификацией скриптов, которые нужно написать.

**База каждый раз собирается заново.** Каталожные данные 2ГИС дрейфуют за недели: в замере
стоматологий клиника потеряла заявленный канал через 2 недели после выгрузки, у двух рейтинг
разошёлся на ≥0.3 звезды. Свежий прогон сборщика стоит минуты — устаревшая база стоит
доверия к рейтингу. Старые CSV не переиспользовать как данные ни при каком дедлайне.

## Роли и железные правила

- **Заявки, сообщения и касания отправляет ТОЛЬКО человек.** Ты готовишь тексты, консоль,
  очередь — жать «отправить» в мессенджерах запрещено, даже если технически можешь.
- **Аккаунты замера ≠ аккаунт выдачи.** Замер идёт с обычных личных аккаунтов — так, как пишет
  любой клиент; скоркарты и любые деловые касания — с отдельного официального аккаунта (имя,
  фото, описание замера). Смешение контуров портит замер: компания, узнавшая проверяющего,
  отвечает уже не как обычному клиенту, и результаты перестают быть сравнимыми.
- **н.д. ≠ 0.** Проверенное отсутствие — ноль баллов; непроверенное — выпадает из знаменателя.
  Каждая выдача места — с пометкой «проверено X из Y баллов». Ранжирование — по нормированному
  пассиву, сырые баллы рядом.
- **Публично — только анонимные агрегаты** (ст. 152 ГК РФ, деловая репутация: компании публично
  не позорим). Имена в негативном контексте не публикуются; лидер называется только с его
  письменного согласия.
- **Без питча и без тайн о методе.** В выдаче нет цен, предложений и рекламы, язык — язык
  клиента. Как мерили, рассказываем прямо, включая то, что сбор и подготовка данных делались
  с помощью ИИ (см. «Этика замера»).
- **Веса и шкалы фиксируются ДО волны (v1.0) и не меняются задним числом.** Иначе рейтинг
  превращается в подгонку. Изменения — только в v1.1 к следующей волне.
- Пользователь работает **удалённо**: офлайн-обходов нет, вся выдача — мессенджер/почта/звонок.

## Этика замера (mystery shopping)

Замер — это проверка сервиса под видом обычного клиента (mystery shopping). Его рамки не
обсуждаются ни при каком дедлайне:

1. **Один настоящий вопрос.** Каждая компания получает одну заявку о реальной услуге — такую,
   какую задал бы обычный клиент. Без выдуманной боли, без записи на приём, на который никто не
   придёт, без брони времени специалиста и без давления: замер не должен стоить компании больше,
   чем обычный вопрос клиента.
2. **Результаты публикуются только анонимно.** Наружу — агрегаты по городу; компании не
   называются и не узнаются по деталям. Персональная скоркарта уходит только самой компании —
   бесплатно и без условий.
3. **После замера — полная открытость.** На вопрос «что это и зачем» отвечаем сразу и честно:
   независимый замер, одинаковый по смыслу вопрос N компаниям ниши. Про использование ИИ в работе
   (сбор данных, расчёт, подготовка текстов) говорим открыто — в подписи скоркарты и в ответ на
   прямой вопрос. Сообщения при этом пишет и отправляет человек.
4. **Только открытые данные и законные способы.** Публичные карточки, сайты и официальные API —
   в рамках условий площадок. Капчи, блокировки и лимиты не обходим; ключи API — только свои и
   никогда не в репозитории.
5. **Меряем процесс, а не людей.** Личные аккаунты сотрудников не ищем, персональные данные не
   собираем; в скоркарте — «не предложили время», а не «администратор плохо работает». Служебные
   данные (ИНН, руководитель) нужны только для адресной доставки и не публикуются.

## Фазы конвейера

Каждая фаза — чек-пойнт: покажи пользователю результат и получи «дальше», прежде чем жечь
время на следующую. Подробности каждой фазы — в references/, читай по мере входа в фазу.

### Фаза 0 — Вводные (30 минут)
Зафиксируй: ниша, город, целевой сегмент (кому продаём) и **сегмент вне зачёта** (кому не
продаём и кого исключаем из рейтинга целиком — у стоматологий это были госполиклиники; в
нише пользователя реши с ним: филиалы федеральных сетей? муниципальные конторы?).
Любой стартовый план/бриф, который ты пишешь в этой фазе, начинается с «железных правил» и
«этики замера» выше — они задают рамку с первого дня (кто шлёт заявки, какие аккаунты, что
публично, что говорим о методе), даже если сами фазы ещё далеко.

### Фаза 1 — Разведка источников (полдня) → `references/01-разведка-и-база.md`
Протокол **API-first**: прежде чем сажать браузерного агента на любой сайт — 15 минут ищи
публичный или официальный API и проверь условия его использования. Урок конвейера: полдня
работы браузерного агента по отзывам 2ГИС (с ошибками сортировки и сожжённым контекстом)
заменились скриптом на 6 минут, когда нашёлся публичный API. Проверь источник 2-3 запросами
и сверь цифры с живой карточкой ГЛАЗАМИ прежде чем масштабировать на весь город.

### Фаза 2 — База и бренды (полдня) → `references/01-разведка-и-база.md`
Точки → бренды (склейка в 2 ступени: телефон, затем город+домен/слаг с GENERIC-guard),
сегмент вне зачёта помечается, но не удаляется. После старта волны база **заморожена**.

### Фаза 3 — Методика v1.0 (полдня) → `references/02-методика-шаблон.md`
Шаблон весов: **B отклик 40 / карты 20 / ИИ-видимость 15 / сайт 15 / агрегаторы 10** — блоки
универсальны, шкалы адаптируй под нишу вместе с пользователем. Запиши МЕТОДИКА.md и веса.json
по образцу эталона. Freeze.

### Фаза 4 — Пассивный сбор (1-2 дня, параллелится) → `references/04-пассивные-слои.md` + `references/06-делегирование.md`
Сайты, карты, соцсети, агрегаторы ниши, ИИ-тест, глубокий слой отзывов. Всё, что можно —
API-скриптами в основной сессии; браузерное — дешёвым субагентам по шаблонам из 06.
Обязателен **спот-чек**: 5-6 компаний разных профилей, цифры скрипта против живой карточки.
Расхождение = стоп и разбор (урок: API 2ГИС отдаёт отзывы, которых посетитель не видит —
фильтр is_rated нашёлся только спот-чеком).

### Фаза 5 — Волна замера (вечер + среда + утро четверга) → `references/03-волна-замер.md`
HTML-консоль с уникальными текстами заявок, ротацией аккаунтов и полем комментария.
Пользователь шлёт руками, ты собираешь фиксацию и гонишь конвертер. Три исхода отправки,
скорость от **открытия** компании, тишина = проверенные нули только при закрытии замера.

### Фаза 6 — Расчёт и бенчмарки (полдня) → `references/02-методика-шаблон.md`
Индекс /100, xlsx со сводом, «проверено X из Y» везде. **Бенчмарки города** (квартили по
каждой метрике) — главная ценность продукта: выборки всего города нет ни у кого, кроме нас.
В каждой скоркарте компания сравнивается с медианой и четвертями города.

### Фаза 7 — Выдача, полностью удалённая → `references/05-выдача-удалённая.md`
Скоркарты по канону (заявка → место → 2 наблюдения с обязательным плюсом → 1 бесплатная
рекомендация → подпись-метод; без питча), сопроводы, агрегаты. Доставка с официального
аккаунта в живой мессенджер компании; канал мёртв → email → звонок. Перед касаниями —
рефреш слоя отзывов (10 минут), чтобы в разговоре был вчерашний факт.

## Инструменты эталона: что копировать и что адаптировать

| Скрипт | Что делает | Что менять под новую нишу |
|---|---|---|
| `индекс_база.py` | CSV → бренды, склейка, каналы | путь CSV, маркеры сегмента вне зачёта, GENERIC-слова |
| `аудит_2gis_отзывы.py` | отзывы 2ГИС через публичный API | только источник брендов; API-часть универсальна |
| `аудит_яндекс.py`, `аудит_соцсети.py`, `аудит_агрегаторы.py` | пассивные слои | агрегаторы ниши (см. 04) |
| `ии_консоль.py` | консоль ИИ-теста | вопросы под нишу, словарь брендов (weak-слова!) |
| `волна_сборка.py` | генератор волны + TEMPLATE консоли | пулы услуг/текстов под нишу; main() запускать только ДО первой отправки |
| `консоль_синк.py`, `волна_дозаказ.py` | пересборка HTML, дозаказ | почти без правок |
| `замер_конвертер.py` | консоль → b_замер + канал_статус | маппинги градаций, если шкалы менялись |
| `индекс_расчёт.py` | расчёт /100 + xlsx | шкалы блоков из новой методики |
| `артефакты.py` | скоркарты, агрегаты, бенчмарки | формулировки дыр/похвал под нишу; секцию шпаргалок очного обхода можно не использовать |

Тесты: у эталона есть смоук-паттерны (headless-прогон консоли через node со стабами,
синтетическая фиксация → конвертер → расчёт → артефакты). Повтори их в новом проекте —
они ловили реальные баги на каждом шаге.

## Ритм и чек-пойнты

Реалистичный календарь одной волны: пн-вт — фазы 0-4; вт вечер — волна; ср — логирование
ответов; чт — закрытие, расчёт, скоркарты, спот-чек пользователем 3 случайных компаний
(15 минут) ДО отправки; чт-пт — касания. Git-коммит после каждой фазы, данные волны и
пруфы — в .gitignore (пруфы датированные, оригиналы не публикуются).
